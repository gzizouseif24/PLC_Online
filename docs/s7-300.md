# S7-300: plan

Why the S7-300 next: it is the PLC met most often in the field (often as Profibus DP master
with WAGO slaves), and the one where understanding the program logic is the most feasible:
uploading blocks is part of the S7 protocol, and the compiled code (MC7) has been decoded
publicly (DotNetSiemensPLCToolBoxLibrary converts MC7 to STL, LGPL).

Brands met in the field, by frequency: S7-300 (most), Omron, S7-1200, TSX, Panasonic, Fatek (once).

Link: USB MPI adapter + STEP 7's S7ONLINE driver through libnodave (Windows, 32-bit Python),
as in `tools/siemens.py` today. Everything below works on what the PLC holds: no STEP 7
project needed.

## Reference to get first

Siemens *System Software for S7-300/400 — System and Standard Functions* (reference manual):
the system status lists (SZL) and the diagnostic buffer event codes. Check every SZL number
against it before coding: blog sources contradict each other. Same method as Omron with W342.

## Progress

- Step 1 coded (31/10): `tools/siemens.py etat` reads SZL 0111 (order number, versions), 011C
  (names, serial number), 0174 per LED (SF, RUN, STOP, FRCE, BAF, BUS1F, BUS2F: mode, faults,
  forces) and 0232 index 4 (key switch, protection level, program / HW config checksums).
  Formats from the Siemens manual A5E02790053-01 (05/2010), chapter 34. Cycle time: no status
  list for it in the manual, left for later.
- **Bench 31/10, CPU 315-2DP (6ES7 315-2AF03-0AB0), firmware V1.2.0:** all reads answer;
  libnodave returns the SZL header (ID, index, LENTHDR, N_DR) before the records. Old-CPU
  quirks: record index 0000 for index 1; index 6 answered like index 1 (no hardware version);
  011C (names, serial number) and LEDs BUS1F/BUS2F not supported; checksums present but
  `ken_rel` = 0 (not guaranteed): to test by changing the program.

- Step 2a coded (31/10): `tools/siemens.py diagnostic` reads the diagnostic buffer (SZL 00A0,
  §34.29) and names each event from the 546 event IDs of chapter 35
  (`plc_online/protocols/s7_events.py`, English texts as in the manual). The 5 info words are
  shown raw for now (meaning depends on the event): decode the common ones from bench samples.
- **Bench 31/10:** 10 entries read (208 bytes, one PDU). CPU clock wrong (2005). Every startup
  logs two `5961` "Parameter assignment error", info `FF06 C17B 0001 0004 8B07` and
  `... 0000 8B07`: the `0004` / `0000` may be the addresses of the SM 322 / SM 321. To decode
  with STEP 7's "details on event" for the same entries. Next: modules, then DP slaves (WAGO).

- Step 3a coded (31/10): `tools/siemens.py modules` reads SZL 0D91 index 0 (§34.23, all modules
  of rack 0): slot, first address, inputs / outputs, state (error, absent, disabled). No order
  number for I/O modules in any status list. **Not yet run on the bench.**

## Steps, in order

| # | Feature | How | Notes |
|---|---|---|---|
| 1 | CPU state: order number, firmware, mode, key switch, protection level, cycle time (min / max / current) | SZL reads | documented |
| 2 | Diagnostic buffer (events with date and time, in plain text) | SZL, event code table from the manual | documented |
| 2 | DP bus: which slaves answer / are missing (WAGO slaves), slave diagnostics | SZL 0x0692 and DP diagnostic lists | documented |
| 3 | Modules in the racks and their state; detailed module diagnostics (wire break, missing supply...) | SZL module lists and diagnostic records | documented |
| 4 | Active forced values (FRCE light) | to check in the manual | technicians forget forces |
| 5 | Block list with date, size, checksum: "has the program changed?" against a reference | block list / block info | documented in libnodave |
| 5 | Program backup and restore (all blocks) | block upload / download | as on TSX |
| 6 | Signal recorder: inputs / outputs with timestamps, good cycle vs faulty cycle | fast polling | paid tools exist (PLC ANALYZER, iba, ServiceLab): price advantage |
| 7 | Logic: MC7 → STL → logic model (output ← conditions); "why is this output off", cross-references, fault bits, cycle step | follow the public decoder | LGPL: keep the decoder in the open part if open core |
| 8 | Module parameters from HW Config (analog ranges, DP addresses...) | system data blocks (SDB), format not documented: decode by comparison | longest |

## Later, other brands

- Logic for TSX and Omron: decode by comparison (`docs/logique.md`, test programs in
  `research/tsx/programmes_test/`).
- S7-1200 and other Ethernet PLCs (Allen-Bradley, CODESYS, OpenPLC): read values only at
  first (snap7, libplctag / pycomm3, OPC UA, Modbus). Their program formats are harder or
  protected.

# Siemens S7-200 over PPI

## Sources

- **libnodave 0.8.5** (`nodave.c`, `testPPI.c`, `testPPIload.c`): PPI link layer and the S7 PDUs it
  sends to S7-200 CPUs (read / write, STOP / RUN, block list, block upload, block load).
- **S7-200 System Manual** (A5E00307987-04):
  - SM bits and the CPU / module identification bytes (appendix D);
  - memory sizes (table 6-1);
  - I/O addressing (figure 4-11, used as a test case).

## What the tool does (`plc_online/protocols/ppi.py`, `plc_online/web/s7200_web.py`)

- **Link:** RS-232/PPI cable on a COM port, 9600 bauds 8E1, PLC address 2, PC address 0. It is pure
  Python, so it needs no Siemens software and no 32-bit Python.
  - The PC sends a request (`68 L L 68 DA SA 6C <PDU> FCS 16`) and the PLC answers `E5`.
  - The PC then asks for the reply with `10 DA SA 5C FCS 16`, alternating 5C / 7C while the PLC
    answers `E5` (not ready).
  - The reply comes as `68 L L 68 SA DA 08 <PDU> FCS 16`.
- **Status:**
  - CPU type from SMB6 (224 vs 224XP from the V memory size);
  - switch position (SM0.7);
  - faults: SM4.3 run-time problem, SM4.7 forcing, SM5.0..5.3 I/O, module error bytes;
  - scan times SMW22..26.
- **Modules:** SMB8..SMB21 decoded (present, type, number of I/O, errors). Addresses are allocated
  as the manual says: digital I/O by byte, analog by 2 channels, inputs and outputs counted separately.
- **Watch:** I, Q, M, V, SM (bits, B, W, D), AIW, AQW. Writes: Q, M, V, SM30 and up, AQ.
- **Data:** the whole V memory to CSV, then restore of the changed bytes only.
- **RUN / STOP:** the S7 PI services `P_PROGRAM` (libnodave `daveStart` / `daveStop`).
- **Program:** list and upload of every OB, DB and SDB block, kept as they are. Save, compare
  block by block, download / import.

## Bench plan

PC with Micro/WIN, the RS-232/PPI cable and a bench S7-200. Send the folders and files produced.

**1. Link and status** (Micro/WIN closed):

```
python tools/s7200.py etat --port COM1 --trace
python tools/s7200.py brut --port COM1
```

Do both in RUN and in STOP (switch, or Micro/WIN), then send the output.

**2. Upload, compared with Micro/WIN:**

```
python tools/s7200.py televerser --port COM1 bench_P0
```

**3. Decoding: one small test program at a time.** For each test:

1. Write the program in Micro/WIN.
2. Download it to the bench CPU.
3. Run `televerser` into a folder named after the test.
4. Export the program as text (*File > Export*, `.awl`).

| Test | Main (OB1) |
|---|---|
| P0 | empty |
| P1 | `LD I0.0` / `= Q0.0` |
| P2 | `LD I0.1` / `= Q0.0` (same as P1, other input) |
| P3 | `LDN I0.0` / `= Q0.0` |
| P4 | `LD I0.0` / `A I0.1` / `O M0.0` / `= Q0.1` |
| P5 | `LD SM0.0` / `MOVW VW0, VW2` |
| P6 | `LD SM0.0` / `+I VW4, VW6` |
| P7 | `LD I0.0` / `TON T37, 100` |
| P8 | `LD I0.0` / `LD I0.1` / `CTU C0, 10` |
| P9 | `LD SM0.0` / `CALL SBR_0`, SBR_0 = `LD I0.2` / `= Q0.2` |
| P10 | `LD SM0.1` / `ATCH INT_0, 10`, INT_0 = `LD SM0.0` / `INCW VW8` |
| P11 | P1, plus data block `VW0 1234` / `VB10 'ABC'` |
| P12 | P1, system block: port 0 at 19.2 kbauds |

Comparing P1 with P2 (one operand changed), P1 with P3 (one opcode changed), and so on gives the
encoding one instruction at a time.

**4. Capture of Micro/WIN's own upload and download** (for restore):

1. Install com0com: virtual pair COM10 <-> COM11.
2. In Micro/WIN, set the PG/PC interface to PC/PPI cable on COM10.
3. Run `python research/s7200/ppi_proxy.py COM11 COM1`.
4. In Micro/WIN, upload the program, then download P1. Type a note in the proxy window before each
   operation.
5. Send `s7200_capture.log`. It decodes with `python research/s7200/ppi_decode.py s7200_capture.log`.

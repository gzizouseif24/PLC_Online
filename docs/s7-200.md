# Siemens S7-200 over PPI

## Sources

- **libnodave 0.8.5** (`nodave.c`, `testPPI.c`, `testPPIload.c`): PPI link layer and the S7 PDUs it
  sends to S7-200 CPUs (read / write, STOP / RUN, block list, block upload, block load).
- **S7-200 System Manual** (A5E00307987-04):
  - SM bits and the CPU / module identification bytes (appendix D);
  - memory sizes (table 6-1);
  - I/O addressing (figure 4-11, used as a test case).

## What the tool does (`plc_online/protocols/ppi.py`, `plc_online/web/s7200_web.py`)

- **Link:** RS-232/PPI cable on a COM port, 9600 bauds 8E1, PLC address 2, PC address 0. It is pure
  Python, so it needs no Siemens software and no 32-bit Python.
  - The PC sends a request (`68 L L 68 DA SA 6C <PDU> FCS 16`) and the PLC answers `E5`.
  - The PC then asks for the reply with `10 DA SA 5C FCS 16`, alternating 5C / 7C while the PLC
    answers `E5` (not ready).
  - The reply comes as `68 L L 68 SA DA 08 <PDU> FCS 16`.
- **Status:**
  - CPU type from SMB6 (224 vs 224XP from the V memory size);
  - switch position (SM0.7);
  - faults: SM4.3 run-time problem, SM4.7 forcing, SM5.0..5.3 I/O, module error bytes;
  - scan times SMW22..26.
- **Modules:** SMB8..SMB21 decoded (present, type, number of I/O, errors). Addresses are allocated
  as the manual says: digital I/O by byte, analog by 2 channels, inputs and outputs counted separately.
- **Watch:** I, Q, M, V, SM (bits, B, W, D), AIW, AQW. Writes: Q, M, V, SM30 and up, AQ.
- **Data:** the whole V memory to CSV, then restore of the changed bytes only.
- **RUN / STOP:** the S7 PI services `P_PROGRAM` (libnodave `daveStart` / `daveStop`).
- **Program:** list and upload of every OB, DB and SDB block, kept as they are. Save, compare
  block by block, download / import, and **load back** (restore, CPU in STOP), with the sequence of
  libnodave `testPPIload.c`:
  1. Load request `1A 00 01 00 00 00 00 00 09 _0<type><number>P 0D 1<total size, 6 digits><code size, 6 digits>`.
  2. The PLC then asks for each part with a request `1B`. The PC answers with an ack-data PDU in an SD2
     frame with FC 5C: param `1B 01` (more) or `1B 00` (last), data `<length 2 bytes> 00 FB <bytes>`
     (up to PDU size - 22).
  3. The PLC ends with `1C`, the PC answers `1C`.
  4. The PI service `28 … FD 00 0A 01 00 0<type><number>P 05 _INSE` links the block.

## Seen on the bench CPU 224 (6ES7 214-1AD23-0XB0, 16/11)

- Read, SM bits and area 03 work as described above.
- SMB0 toggles between F1 / B1 / D1 / 91 in RUN: SM0.5 and SM0.6 move, so RUN is detected.
- Absent expansion slots read FF.
- **A reply can be lost after E5.** If the PC then sends a new request, the PLC answers
  `10 00 02 02 04 16`: an SD1 frame with function 02 ("busy"), because the old reply is still
  waiting. The driver now asks again for the lost reply, and on "busy" collects the pending reply
  before resending.

### Blocks after Micro/WIN loaded an empty project (16/11, `research/s7200/bench_P0/`)

Trace: `research/s7200/bench_P0_trace.txt`.

| Block | Listed | Upload | Content |
|---|---|---|---|
| OB1 | yes | 106 bytes | the program: MAIN, SBR_0 and INT_0 together |
| DB1 | yes | 56 bytes | the data block (V memory initial values) |
| SDB0 | yes | 332 bytes (2 parts) | the system block (ports, retentive ranges, outputs in STOP…) |
| SDB2 | yes | **refused (D209)** | not uploadable: left out of the copies |

- Every block starts with the same 36-byte header as an S7-300 MC7 block:
  - `70 70`, then the type at byte 5 (08 OB, 0A DB, 0B SDB) and the number at bytes 6-7;
  - the total size at bytes 8-11, a password at bytes 12-15 (0 = not protected);
  - two time stamps: ms since midnight + days since 1984-01-01. Both read **2026-11-16 14:20:55**, the
    time of the Micro/WIN download;
  - the code size at bytes 34-35 (OB1: 16 bytes for an empty program).
- **OB1 and DB1 hold a zlib stream** (`78 9C`), after the code and 4 bytes (`06 00 41 00`: 0x41 = 65,
  the inflated size). It is Micro/WIN's own description of the program: the inflated OB1 holds the
  names MAIN, SBR_0 and INT_0 (length-prefixed), and the inflated DB1 holds the page name USER1. This is
  what Micro/WIN gets back on upload. Decoding the instructions starts from this stream, not from the
  compiled code.

### Decoding into STL (`plc_online/protocols/s7200_code.py`)

Checked against Micro/WIN's own STL export of two bench programs, line by line (tests `DecodeTests`):
- `research/s7200/machine_banc/`: SBR10 'Allgemein'.
- `research/s7200/programme2/`: OB1 with 118 networks.

- **The zlib stream is the table of contents.** It starts with the byte size of every item of the code
  (16-bit little-endian), up to the code size. Then there is one record per POU: type (0A main, 0B SBR,
  0C INT), record length, number, number of items, name.
  - Main = (prologue + Network 1) + networks + MEND.
  - SBR / INT = label + networks + RET / RETI.
- **Short bit instructions are 2 bytes:** the high nibble is the operation (0 LD, 1 LDN, 2 A, 3 AN, 4 O,
  5 ON, 6 =), then area (3 bits: 0 I, 1 Q, 2 M, 4 SM, 5 T), bit (3), byte (6). Timer n = byte n // 8,
  bit n % 8.
- **Long bit operand** (V, bytes above 63):
  - opcode `8x` (x = the same operation);
  - operand `<area nibble | bit*2> <byte>`, area 8 = V (`84 0D` = V13.2);
  - above byte 255: `<F0 | bit*2> <area byte> <address 2 bytes>` (`F8 80 03 84` = V900.4).
- **Word operand:** 2 bytes, area nibble + 12-bit address (`83 F2` = VD1010).
- **Word instructions** have a flags byte: 0x40 = first operand is a constant, 0x04 = second one.

  | Instruction | Bytes |
  |---|---|
  | OLD / ALD | `DD` / `DC` |
  | EU | `E1` |
  | TON Tn, PT | `A6 <flags> <n> <PT constant or word>` |
  | S / R bit, N | `FE 1F / FE 21 01 <long bit> 40 <N>` |
  | MOVW / MOVD | `D9` / `DA <flags> <in> <out>` |
  | MOVB | `D8 …` (deduced) |
  | LDW<= / LDW>= | `96` / `98 <flags> <in1> <in2>` |
  | INCW / INCD | `B1 0C` / `B2 0C <operand>` |
  | CALL SBRn | `D5 <n>` |
  | SBR / INT labels | `D6 <n>` / `CD <n>` |
  | MEND / RET / RETI | `ED` / `E9` / `E5` |
- Anything else prints as `?? <hex>`, never guessed. A deduced instruction is marked `// ?`.

Web: Programme tab, *Details* of a copy. CLI: `python tools/s7200.py stl FOLDER`.

## Bench plan

PC with Micro/WIN, the RS-232/PPI cable and a bench S7-200. Send the folders and files produced.

**1. Link and status** (Micro/WIN closed):

```
python tools/s7200.py etat --port COM6 --trace
python tools/s7200.py brut --port COM6
```

Do both in RUN and in STOP (switch, or Micro/WIN), then send the output.

**2. Upload (done 16/11: `bench_P0`) and load back:**

```
python tools/s7200.py televerser --port COM6 bench_P0
```

Then download P1 from Micro/WIN, close Micro/WIN, and load P0 back with the tool:

```
python tools/s7200.py charger --port COM6 bench_P0
```

The tool first saves the current program next to the folder (`bench_P0_avant_…`), then puts the CPU in
STOP, loads OB1, DB1 and SDB0, and uploads them again to compare. Then switch the power off and on,
and run `televerser` again: the blocks must still be P0.

**3. Decoding: one small test program at a time.** For each test:

1. Write the program in Micro/WIN.
2. Download it to the bench CPU.
3. Run `televerser` into a folder named after the test. It also writes `OB1.source.bin` (the inflated
   zlib stream) next to `OB1.bin`.
4. Export the program as text (*File > Export*, `.awl`).

| Test | Main (OB1) |
|---|---|
| P0 | empty |
| P1 | `LD I0.0` / `= Q0.0` |
| P2 | `LD I0.1` / `= Q0.0` (same as P1, other input) |
| P3 | `LDN I0.0` / `= Q0.0` |
| P4 | `LD I0.0` / `A I0.1` / `O M0.0` / `= Q0.1` |
| P5 | `LD SM0.0` / `MOVW VW0, VW2` |
| P6 | `LD SM0.0` / `+I VW4, VW6` |
| P7 | `LD I0.0` / `TON T37, 100` |
| P8 | `LD I0.0` / `LD I0.1` / `CTU C0, 10` |
| P9 | `LD SM0.0` / `CALL SBR_0`, SBR_0 = `LD I0.2` / `= Q0.2` |
| P10 | `LD SM0.1` / `ATCH INT_0, 10`, INT_0 = `LD SM0.0` / `INCW VW8` |
| P11 | P1, plus data block `VW0 1234` / `VB10 'ABC'` |
| P12 | P1, system block: port 0 at 19.2 kbauds |

Comparing P1 with P2 (one operand changed), P1 with P3 (one opcode changed), and so on gives the
encoding one instruction at a time.

**4. Capture of Micro/WIN's own upload and download** (for restore):

1. Install com0com: virtual pair COM10 <-> COM11.
2. In Micro/WIN, set the PG/PC interface to PC/PPI cable on COM10.
3. Run `python research/s7200/ppi_proxy.py COM11 COM6`.
4. In Micro/WIN, upload the program, then download P1. Type a note in the proxy window before each
   operation.
5. Send `s7200_capture.log`. It decodes with `python research/s7200/ppi_decode.py s7200_capture.log`.
